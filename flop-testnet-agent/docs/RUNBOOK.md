## 5. Выбрать один режим, не смешивая полномочия

| Режим | Результат | Условия |
|---|---|---|
| Диагностика | Состояние установленного агента | Не открывает модель и доставку |
| Получение сохранённого результата | Уже созданный артефакт | Без повторной задачи, discovery, модели и отправки |
| Однократный сбор публичных источников | Сохранённые события и пределы покрытия | Только ранее разрешённое публичное чтение; новая модельная работа может остаться BLOCKED |
| Выполнение одной модельной задачи | Проверенный артефакт | Отдельное действующее разрешение на задачу, модель и бюджет |
| Доставка одного уведомления | Подтверждение сервиса либо UNKNOWN | Отдельное разрешение, конкретные уведомление и получатель |
| Постоянный пилот / scheduler | Повторяющаяся работа | Отдельное решение владельца о режиме, бюджете, доставке и остановке |
| Операции FLOP testnet | Подтверждённые действия в сети | Проверенные актуальные интерфейсы и отдельные разрешения; локальная приёмка этого не заменяет |

Наличие незавершённой задачи или PENDING-уведомления не является командой выполнить их. Для сохранённого результата не запускать обычный путь, если он может одновременно обработать другие события или всю очередь.

### 6.4. Продолжение конкретной разрешённой задачи

Шаблон: заменить путь на согласованный существующий run с сохранёнными входами.

$runDirectory = 'runtime/OWNER_APPROVED_EXISTING_RUN'

Флага `--task-id` нет. Стабильный ID определяется спецификацией, входами и путём артефакта; проверить его соответствие разрешённой задаче. Не менять inputs для обхода блокировки. ## 7. Перед первой новой модельной задачей или доставкой

Использовать существующий механизм политики, не вводить вторую независимую систему разрешений в markdown. Решение владельца должно однозначно определять:

- конкретную задачу или уведомление и срок действия разрешения;
- провайдера и модель, предел расходов на задачу и за день, включая retries и дочерние вызовы;
- допустимый результат и условие остановки;
- для доставки — разрешённого получателя, подтверждённого в локальной конфигурации, и допустимое число попыток.

Точные ID получателя и credentials не включать в публичный runbook. Не выбирать адрес по отображаемому имени или последнему активному чату. Сохранённое подтверждение владельца не отменяет проверок кода: адаптер сверяет числовой адрес и username. При несовпадении остановиться и уточнить привязку; не обходить проверку.

Разрешение модели не разрешает доставку; разрешение доставки не разрешает повторное выполнение задачи. Суффикс `:free` не считать доказательством нулевой стоимости. При неизвестном исходе изменяющего состояние запроса сначала сверять его судьбу, а не отправлять новую операцию наугад.

| Источник недоступен / история утрачена | PARTIAL / HISTORY_LOST; не выдавать за отсутствие событий |
| Модельный анализ не выполнен | Сообщить, что анализ не выполнен, не «новых возможностей нет» |
| Внешнее действие могло состояться, ответ потерян | UNKNOWN / reconciliation; не дублировать без основания |
| Уведомление принято сервисом | Сохранить подтверждение; не объявлять прочтение пользователем |
| Обнаружены откат, конфликт, несовместимость состояния | Сохранить доказательства, остановить соответствующий путь |

При остановке использовать механизм самого проекта. Не удалять записи outbox, события, locks или lease вслепую ради продолжения. Не останавливать все процессы Python на машине.

Rollback выполнять только по локальному плану, учитывающему код, окружение и SQLite вместе. Не затирать изменившееся после backup состояние. Если появились новые записи или внешние действия, сначала установить безопасный способ возврата.

## 9. Зафиксировать результат каждого запуска

В существующем журнале/отчёте достаточно записать:

```text
RUN / TASK / NOTIFICATION: только применимые идентификаторы
STARTED_AT / FINISHED_AT: UTC; пользователю также Asia/Almaty
INSTALLED_COMMIT / PYTHON:
MODE / AUTHORIZATION_SCOPE:
SOURCES_READ / UNAVAILABLE / COVERAGE_GAPS:
RESULT: COMPLETED / BLOCKED / PARTIAL / UNKNOWN / FAILED
ARTIFACT: путь и hash, если создан или повторно получен
NEW_MODEL_CALLS / COST: фактические значения; неизвестное не считать нулём
LIVE_SEND_REQUESTS / SERVICE_RESULT:
FLOP_ACTIONS / SETTLEMENT / REWARD: не смешивать с локальной задачей
PROCESS_STATE_AFTER_RUN:
PERMISSIONS_AFTER_RUN:
```

Не создавать новый отчётный фреймворк. Для одиночного запуска проверить, что он не оставил неразрешённого фонового worker. Постановку в очередь, heartbeat и ответ модели не называть завершённой работой.
